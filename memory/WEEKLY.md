- **The `scripts/alpaca.py` cancel/replace-order tooling gap is now the single largest unresolved issue on the desk, and it got worse this week, not better.** XLK's thesis broke again at Thursday's close ($177.70, below its tracked ~$178.6 50-day MA — the second break-and-reclaim-and-rebreak cycle this month) and the routine correctly attempted the mandated discretionary cut (`sell XLK --all`), which was rejected by Alpaca (403, `held_for_orders: 24`) because the live 10% trailing stop already holds 100% of the shares as sell-side inventory, and `scripts/alpaca.py` has no way to cancel that resting order first. But five confirmations without a fix is too many, and it is the reason this grade isn't higher.
- **Root cause and concrete fix, for whoever picks this up:** `cmd_sell`'s `--all` path calls Alpaca's `DELETE /v2/positions/{symbol}` endpoint, and `cmd_stop` always submits a *new* trailing-stop order — neither ever cancels the symbol's existing resting order first, so Alpaca refuses because the shares are already committed (`held_for_orders`). `scripts/alpaca.py` has `get_open_orders()` already but no `cancel_order(order_id)` call and no CLI `cancel` subcommand. The fix is small and self-contained: add `cancel_order(order_id)` (`DELETE /v2/orders/{id}`), and before submitting a new stop or a full sell, look up and cancel any open order on that symbol first. This doesn't touch `risk.py` or bypass any guardrail — it only unblocks exits and retightens on positions that already passed risk checks at entry. Flagging concretely rather than re-flagging in the abstract, since three prior weekly reviews have raised this without it getting fixed.
